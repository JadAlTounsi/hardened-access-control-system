# ADR-003: Deciding between MFRC522 and PN532

**Status:** Accepted

**Date:** 08/17/2026

## Context
I have both the MFRC522 and PN532 modules available to use for the access control project. The primary ESP32-S3 controller must manage a 3x4 matrix keypad, an LCD screen, a buzzer, and the RFID reader while linked to an ESP32-S3 CAM board.

I am comparing these 2 modules to figure out the smartest pin layout, what makes the most sense for the actual use case, and whether I want to support NFC phone tapping instead of just basic RFID cards.

While installing the PN532, I reversed the polarity of the power pins and short circuited the module which ended up frying the module.

## Decision
Use RC522 for RFID reader due to the PN532 being unusable now. Since both readers are security equivalent with the MIFARE cards I have, I'm going to use the RC522 module as it is the only one working that I currently have, and the usage of pins isn't much of an issue to me.

## Options Considered

### Option 1: PN532
- Positive: Reads NFC so you can unlock with a smartphone rather than a card.
- Positive: Can run on I2C to share the same 2 wires as the screen which saves pins on the ESP32.
- Negative: A little bit more expensive than the MFRC522.
- Negative: Getting the NFC communication to work between the smartphone and PN532 module could be difficult to setup.

### Option 2: MFRC522
- Positive: Simple to use and get running.
- Positive: Very cheap and works with cards and fobs.
- Negative: Restricted to MIFARE cards with insecure cryptography.
- Negative: Takes up 5 pins on the ESP32.

## Consequences
- Positive: I would've used SPI for either PN532 or RC522 so pin usage isn't an issue.
- Positive: Security is unaffected as that lives in the card rather than the reader.
- Negative: Can't upgrade to a stronger card type.
- Negative: Fried my PN532 module while testing.
