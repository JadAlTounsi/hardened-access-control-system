# ADR-001: Build insecure first, then attack and harden

**Status:** Accepted

**Date:** 07/27/2026

## Context
This project's goal isn't just a working smart lock. Many ESP32 access control builds already exist publicly. The goal is to demonstrate a security assessment process: finding real 
vulnerabilities and fixing them rather than securing it from the start or leaving it insecure with no fix.

## Decision
1. Build a fully functional access control system with no security 
hardening first (plaintext network traffic, no rate limiting, no flash encryption). 

2. Attack it (traffic sniffing, replay attacks, firmware dump, brute forcing). 

3. Document findings, then harden the system and verify each fix against the original attack.

## Consequences
- Positive: Produces before/after evidence for each specific vulnerability
- Negative: Adds more time to the build due to starting insecure, then hardening it, then verifying the solution.
